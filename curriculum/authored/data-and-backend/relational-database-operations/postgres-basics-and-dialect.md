      -- MySQL
      -- CREATE TABLE board (id INT PRIMARY KEY AUTO_INCREMENT, ...);

      -- PostgreSQL (권장: SQL 표준 IDENTITY)
      CREATE TABLE board (
        id       bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
        writer   text,
        title    text NOT NULL,
        content  text,
        is_deleted boolean NOT NULL DEFAULT false,   -- MySQL 의 TINYINT(1) 대신 진짜 boolean
        created_at timestamptz NOT NULL DEFAULT now()

<!-- section: goal -->
## 이 Lesson을 끝내면

- 이 챕터가 **PostgreSQL 기준**인 이유(Supabase = Postgres)를 안다.
- `psql` 로 접속하고 `\l` / `\dt` / `\d` / `\du` 같은 메타명령으로 스키마를 살핀다.
- `data-modeling/sql-essentials` 에서 배운 **MySQL 기준 SQL과 PostgreSQL의 차이**만 안다 —
  `AUTO_INCREMENT` ↔ `GENERATED … AS IDENTITY`/`SERIAL`, `LIKE`/`ILIKE`, 따옴표, `text`/`boolean`/`RETURNING`/`::`.
- Node 드라이버가 `mysql2` 의 `?` 에서 `pg` 의 `$1` 로 바뀌는 것을 안다.

<!-- section: prerequisite -->
## 먼저 알고 있어야 하는 것

- `data-modeling/sql-essentials` 의 CRUD·`WHERE`/`ORDER BY`/`GROUP BY`·JOIN·`?` 파라미터 바인딩(MySQL 문법).
- 관계형 vs 비관계형(`data-modeling/relational-vs-nonrelational`).

<!-- section: dev_problem -->
## 이게 없으면 겪는 문제

지금까지 SQL을 **MySQL 문법**으로 배웠는데, 이 프로젝트가 실제로 쓰는 건 **PostgreSQL**이다
(Supabase가 Postgres 위에 돌아간다). `AUTO_INCREMENT` 를 쳤다가 문법 오류가 나고, `LIKE '%HTML%'` 가
대소문자 때문에 안 잡히고, `mysql2` 코드를 `pg` 로 옮기니 `?` 가 안 먹는다. **이미 아는 SQL은 그대로**
쓰고, "달라지는 지점"만 갈아 끼우면 된다.

<!-- section: concept -->
## 1. psql

{{code: psql}}

`psql` 은 PostgreSQL의 대화형 클라이언트다. SQL 문은 세미콜론으로, 백슬래시로 시작하는 **메타명령**은
세미콜론 없이 친다. Supabase는 Connect 메뉴에서 접속 URL을 준다(로컬 개발이면 `supabase start` 후 로컬 URL).

<!-- section: mechanism -->
## 2. 자동 증가 — IDENTITY

{{code: identity}}

- MySQL `INT PRIMARY KEY AUTO_INCREMENT` → PostgreSQL은 **`bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY`** 를 권장한다
  (SQL 표준, id에 실수로 값 넣는 것을 막음). `SERIAL` 도 동작하지만 표준이 아니다.
- 앱이 id를 직접 넣어야 하면 `GENERATED BY DEFAULT AS IDENTITY`.
- MySQL `TINYINT(1)` 대신 **진짜 `boolean`**, `DATETIME` 대신 `timestamptz`(타임존 포함) 권장.

<!-- section: concept | title: 방언 차이 -->
## 3. 자주 걸리는 방언 차이

{{code: dialect}}

- **따옴표**: `'문자열'`, `"식별자"`. MySQL 백틱은 없다. 따옴표 없는 식별자는 **소문자로 접힌다** →
  컬럼명은 `snake_case` 로 통일하는 게 편하다.
- **`LIKE` 는 대소문자를 구분한다.** 대소문자 무시는 **`ILIKE`**.
- **캐스트**: `x::int` 또는 `CAST(x AS int)`.
- **삽입 후 값 받기**: `INSERT … RETURNING id` (MySQL `LAST_INSERT_ID()` 자리).

<!-- section: concept | title: 드라이버 -->
## 4. Node 드라이버

{{code: driver}}

`mysql2` → `pg`(node-postgres). 플레이스홀더가 **`?` → `$1, $2, …`** 로 바뀌고, 결과는 `result.rows`.
SQL 인젝션 방어 원칙(문자열 조립 금지 + 파라미터 바인딩)은 그대로다.

<!-- section: must_know -->
## 반드시 기억할 것

- 이 챕터는 **Postgres 기준**(Supabase가 Postgres). SQL 개념은 그대로, 방언만 바뀐다.
- `psql`: SQL은 `;`, 메타명령(`\dt` `\d` `\du` `\x`)은 `;` 없이.
- 자동 증가는 **`bigint GENERATED ALWAYS AS IDENTITY`** 권장(SERIAL 대신).
- 식별자는 따옴표 없으면 **소문자로 접힘** → `snake_case`. 대소문자 무시 검색은 **`ILIKE`**.
- 캐스트 `::`, 삽입 후 `RETURNING`, 타입은 `text`/`boolean`/`timestamptz`.
- Node 드라이버 `pg`: 플레이스홀더 **`$1`**, 결과 `result.rows`. 파라미터 바인딩은 여전히 필수.

<!-- section: experiment -->
## 직접 해 보기

1. 로컬 Supabase(`supabase start`) 또는 접속 URL로 `psql` 에 붙어 `\dt` / `\d <테이블>` 로 스키마를 살펴라.
2. `sql-essentials` 에서 만든 `board` 테이블을 Postgres 문법으로 다시 `CREATE TABLE` 하라(`GENERATED ALWAYS AS IDENTITY`, `boolean`, `timestamptz`).
3. `INSERT … RETURNING id` 로 새 행의 id를 즉시 받아 보라.
4. `LIKE '%HTML%'` 와 `ILIKE '%html%'` 결과를 비교하라.
5. `pg` 로 `SELECT … WHERE id = $1` 을 실행하고, `?` 로 바꾸면 어떤 에러가 나는지 확인하라.
6. 컬럼명을 `"createdAt"` (큰따옴표)와 `created_at` 두 가지로 만들어 조회 시 차이를 관찰하라.
